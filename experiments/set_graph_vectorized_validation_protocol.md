# Prospective experiment: vectorize public `set_graph` active-neighbor validation

**Frozen before candidate modification and CI measurement.** Independent draft branch from production `master` at `ababc48986b40f083d5930e922f844aa2ea418b2`. This is an optimization of the public *graph-installation/validation* API only. It must NOT modify the dense padded `neib_list` layout, `build_knn_graph`, `build_graph_from_edge_index`, graph connectivity, backend kernels, class mapping, RNG, or stopping. Do not merge just because regression CI passes.

## Candidate and unchanged contract

Original `PCC.set_graph` validates every active row with a Python loop, then constructs an active-entry mask for conversion. Candidate constructs exactly the already-required mask once, selects active elements once in row-major order, calls the **existing** `validate_finite` and `_check_int64_conversion_range` on that extracted vector, converts to int64 with `copy=False` when safe, checks converted index bounds before state mutation, and copies into a **new** dense int64 matrix. Public neighbors/degrees remain owned copies with unchanged zeros in unused padding, finite coercion/truncation, int64 overflow rejection, shape rules, `k_nn` behavior, error categories and no-mutation-on-failure. No in-place editing of the caller's graph. Float/complex/object/Decimal inputs, exceptions, empty/isolated graphs, NaN/inf in unused padding, non-contiguous/Fortran views, oversized integers, and preexisting fitted state require focused tests. A strict source diff may change only this validation/conversion block plus focused tests and experiment files.

## Prospective checks

1. Native Linux/Windows Python 3.10/3.12 full existing PCC regression must succeed, including all original `set_graph` and atomicity tests.
2. Separate same-host reference-vs-candidate `set_graph` benchmarking uses the **actual Git blob baseline method** from `ababc48986b40f083d5930e922f844aa2ea418b2` and the candidate source, not a hand-rewritten approximation. Arrays represent original padded int64 graphs at (150,20), (569,25), (1797,35), (30000,35), (30000,100), (100000,35) plus invalid/isolated/object/Fortran cases; all active values and degrees deterministic using independent fixed seed 34007. Measure 25 alternating pairs/size, with warm-up, no tracing during CPU samples. Do not pool OS times or omit unfavorable pairs; retain raw pair timings and environment. Check exact graph output and errors, including active/padding treatment and identical atomicity.
3. Separately measure tracked Python/NumPy `tracemalloc` peaks for 5 paired successful installs per size on both OS. Do not call this process RSS. At least one complete seeded native NumPy/Numba/Cython `fit_predict` per real original k10 graph built by each path must preserve all six final state arrays, predictions, stopping metadata and RNG behavior within each backend.
4. Pilot was exploratory, performed on locally reproduced validation fragments, with roughly 2–5x improvement; **not** a valid production speedup measurement. This preregistration does not claim a new result.

**Adoption gate:** exact output/exception/state parity on all preselected controls; no median slowdown >5% for any of the six valid-size CPU cases on either OS, at least 25% median CPU improvement for both 30,000-row graphs on *each* OS, no >10% tracked-allocation-peak regression for any of six shapes, and all four native regression platforms green. If one gate fails, retain draft and report NO-GO, with no post hoc gate adjustment. Even if every gate succeeds, isolate a minimal production PR rather than merging this research branch wholesale.
