## Motivation and non-duplication

The exact source-original full-fit CPU and native-wall experiments #231, #233, #234 showed the genuine greedy weight/roulette path is material, but an oracle skipping it is not implementable (#233) and real Numba prefix binary selection is slower (#234). Past proposals already tested source-level loop fusion (#106/#107/#109), redundant bounds elimination (#114), scratch reduction (#115/#116), saturation-read skipping (#75/#112), array C/F layouts (#98/#100/#104), Numba neighbor view removal (#214) and C/F ownership layout (#229). **Do not re-propose any of those based on this count.**

Original sequential Numba calculates `prob[i] = dominance[next_node, label] * dist_weights[dist_table[next_node,p_i]]` for every greedy neighbor (with original invalid-neighbor fallback), then calculates the cumulative roulette sum. We do **not yet know**, with actual production state and native RNG trajectory fixed, the fraction of candidate weights with **zero dominance**, **saturated 255 distance** or **zero effective product**, and how these fractions vary across real kNN graph/degree/class/policy conditions. Counting without source changes will determine whether a novel *condition-specific* skip hypothesis is even worth discussing. A high zero proportion alone is NOT evidence that skipping multiplication is numerically safe: floating signed zeros, NaN/Inf, underflow, low-level external buffers and RNG threshold strictness remain relevant.
