## Single frozen candidate and functional contract

Original `ParticleCompetitionAndCooperation.__labelPropagation()` ends with:
```python
row_sums = np.sum(self.owndeg, axis=1, keepdims=True)
row_sums[row_sums == 0.0] = 1.0
self.owndeg = self.owndeg / row_sums
```
The original float64 `self.owndeg` is newly allocated inside each fit, then updated by native/NumPy propagation. The final division allocates a **second full `n_nodes × c` float64 array**, even though no further backend step consumes the unnormalized version after propagation. Candidate is **exactly one expression replacement**:
```python
np.divide(self.owndeg, row_sums, out=self.owndeg)
```
No other production changes allowed. This deliberately changes the internal `self.owndeg` storage identity during postprocessing (no new array) while requiring **bitwise-identical contents, shape, dtype, layout, predictions, all remaining model state and backend stop metadata**. If identity of the pre-normalization array is externally observable through a custom injected backend, that exotic aliasing contract is not covered; do **not** claim bytewise identity of object pointers. Check no known original public readout changes.
