## Existing work and precise new question
#215 already proved ~90% less **first fit-only CPU** in a fresh Python interpreter with a compatible Numba disk cache. #217 proved ~49–53% less **whole-program startup-to-first-prediction time** with new sklearn data preparation and a graph created on every run. Neither establishes the **amortized total program CPU/wall across 2, 5, 10 and 20 successive real native fits within one long-lived Python process that builds/sets its graph ONLY ONCE**. This experiment adds a true persistent-model workload, not another Numba movement or stopping optimization and not a redundant N=1 result.

## Real source and model
- Independently import true original `pcc_numba.py` from frozen original Git blob and production cached Git blob as the *real* filesystem-backed module named `pcc_numba` in **a fresh Python interpreter, before `pcc` is imported**. Source-derivation guard: exact four `@njit\n` -> `@njit(cache=True)\n` replacements, all other bytes identical; original high-level `PCC(impl="numba")._get_backend_fn()` must be the native function, no wrapper/monkeypatch in any timed fit. Guard no modification of production sources versus pinned `master`.
- **Three real sklearn offline datasets Wine (178/3 classes), Breast Cancer (569/2), Digits (1797/10)**, `StandardScaler`, exactly original symmetric undirected union kNN10, one new graph construction using existing `FixturePreparer` for 2 alternated balanced 3-labels/class input masks: seeds **70013 and 70117**. Build and set the ordered dense graph **once** per new process; perform **20 successive `fit_predict` calls on the SAME `PCC` instance, WITHOUT re-running `set_graph`, alternately switching these TWO label masks**, with `seed=0,p_grd=.5,delta_v=.1,deltap=1,dexp=2,es_chk=2000,early_stop=True,max_iter=30000`. All 20 fits should run; `max_iter=30000` is a deliberate censored experiment cap, NOT public default 500000.
- Independent Linux/Windows Python3.12 hosted runners, `OPENBLAS_NUM_THREADS=OMP_NUM_THREADS=MKL_NUM_THREADS=NUMBA_NUM_THREADS=1`. **3 datasets×2 first-mask-order seeds×2 real sources (original vs cached production)×2 genuinely new interpreter phases (source cold, source warm after cached compile)×2 OS = 48 distinct interpreter launches**. Each has 20 timed real native fits and 20 *separately performed post-timing diagnostic replay* fits = **960 timed + 960 verification fits**, all with normal original Numba selection, same graph+same model reuse. Counterbalance which version initializes first by first-mask order seed; source paths and Numba disk directory private and stable within each source/dataset/order scenario. Original cache disabled always, production cold MUST save .nbc code, production warm MUST load existing .nbc data; allow up to 32MiB per cache directory.
- For each new interpreter **parent** records globally monotonic `time.perf_counter_ns()` just before spawning; **child** records wall and `time.process_time_ns()` immediately after each fit **1,2,5,10,20**. Thus report cumulative **real process creation+imports+original sklearn graph+same-model all fits** time-to-checkpoint 1/2/5/10/20, and process CPU since creation to each checkpoint. Main run has **NO per-fit SHA, native observer, Numba RNG probes or log messages between time 0 and fit 20**; such verification overhead would corrupt the cumulative timing.

Replay is strictly outside the measured time. Demand timed-final and replay-final six states and Numba RNG equal and **all 20 diagnostic prefix states and native stops identical** between old source, production source, cold and cached warm new Python interpreters and across Linux/Windows.
