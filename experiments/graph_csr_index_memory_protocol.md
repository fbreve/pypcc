## Frozen one-candidate change

The currently merged master creates several full-`nnz` **int64** temporary index arrays, even when SciPy itself chose safe **int32** CSR `indices`/`indptr` types. Replace **only** each of these three occurrences in both builders:

1. `np.repeat(np.arange(n_nodes, dtype=np.int64), degrees)` (or `num_nodes`/`degrees2`) → `np.repeat(np.arange(n_nodes, dtype=adj.indices.dtype), degrees)`.
2. `np.arange(adj.indices.size, dtype=np.int64) - np.repeat(adj.indptr[:-1], degrees)` → same expression with `dtype=adj.indptr.dtype`. The repeated CSR offsets already retain the correct `adj.indptr.dtype`. Use their native width, not a hard-coded int32 that could overflow a large SciPy CSR.
3. `neib_list[row_idx, col_idx] = adj.indices.astype(np.int64)` → `neib_list[row_idx,col_idx] = adj.indices`, allowing NumPy assignment into the unchanged **int64** destination to perform the safe conversion without a full temporary int64 neighbor vector.

No change to `neib_list` `int64` storage or `neib_qt` `int64`, degree counts, deduplication, `max_deg` padding, graph topology, `k_nn`/p, loop cleanup, APIs or return types. NumPy supports int32/int64 arrays as advanced indices; SciPy selects its index width to represent both row positions and number of nonzero entries. If CSR uses int64, this candidate automatically retains that width, so no narrowing or overflow. Do not introduce a topology-specific heuristic.

## Precommitted production candidate gate

To justify extracting a **separate master-based minimal PR**, require (i) all graph, invalid-input and native exact equivalence controls; (ii) **at least 10% reduction in median paired tracemalloc peak** on each of three prespecified high-edge cases (`dense_1000_30000`, `dense_10000_100000`, `dense_30000_100000`) on **both OS**; (iii) no **>10% median paired complete-builder time regression** on **any** of 33 cases on either OS; and (iv) no >5% memory-peak regression for any case. This is a **memory** experiment; a candidate may be slower within small timing noise, but a 10% performance regression is not acceptable. No after-the-fact changes to seeds, cases, thresholds or graph representations. If it fails, archive a transparent negative result and do not merge. If successful, extract only the two tiny source changes and permanent tests; keep science scripts/workflow unmerged, run full wheel/sdist Python3.10/3.12 Windows/Linux regression independently and review before production merge.

A NumPy traced-peak reduction is **not** a precise global process peak reduction. This experiment also does not reduce the size of the required public **dense padded int64** `neib_list`, which can dominate memory on heavy-tailed/high-degree graphs. Alternative CSR graph formats would be a separate algorithm/API redesign requiring model-level validation.
