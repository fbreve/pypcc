## New hypothesis and negative control
Current `fit_predict` does `prepared_classes=np.unique(prepared_labels)`, then filters the `-1` unknown sentinel. This requires `np.unique` to process all graph nodes although semisupervised PCC typically knows only 3/class homes. Previous source-paired sparse mapping #204/#205 optimized **later** known-label mapping, and #206/#207 optimized **later** inverse labels; #202's onehot node initialization received a NO-GO. This is a **different earlier phase**. No other class, inverse mapping or propagation changes permitted.
- Original exact one-hunk `prepared_classes = np.unique(prepared_labels); prepared_classes = prepared_classes[prepared_classes != -1]`. Candidate if `prepared_labels.size >= 1024` uses `prepared_classes = np.unique(prepared_labels[prepared_labels != -1])` and otherwise runs the **unchanged original two lines**. Only this hunk may change; no sampling, no class-frequency assumptions, no alternate sorting, no user-visible API, no caching mutable state across fits.
- New NumPy mask/known-values temporary allocates RAM; **additional memory is acceptable to save CPU**. Benchmark separate tracked Python peak allocation and impose permissive original peak + **16*n +1MiB**; don't optimize RAM by spending CPU. No CSR/sparse conversion.
