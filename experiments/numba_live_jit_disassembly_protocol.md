## Exact prior observation and new single-step question

[#237](https://github.com/fbreve/pypcc/pull/237) collected native exact original Callgrind `--dump-instr=yes` instruction positions, with full original Numba state/MT19937/stop parity. Digits kNN10, original 3 per class mask seed89021, original p_grd=0.5, seed29, 1000 fixed iterations: JIT step instruction offsets `0x3a0`, `0x3a6`, `0x36b` have 206330, 132999, 41882 **SIMULATED L1D read misses**, respectively, under 32KiB/8-way D1 and 8MiB/16-way LL. These are actual same-process compiled JIT instruction offsets but NOT assembly mnemonics, data-buffer identities, hardware cache misses, CPI or CPU speedups.

New **ONE-CASE** feasibility goal: obtain the original Numba **live loaded executable machine bytes in the SAME process that Callgrind profiles**, disassemble those bytes into instruction boundaries/opcodes/operands, and independently join the profile addresses to the original *same-run* JIT pointer. A match may show `movsd` or memory-indexing instructions, but only the addressing formula, NOT the dynamic allocation or Python array they dereference. Do NOT conclude a matrix culprit or recommend layout change until separately proven.
