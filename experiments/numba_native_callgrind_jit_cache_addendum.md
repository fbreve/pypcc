# Callgrind scientific measurement implementation addendum: JIT cache and exact runtime symbol-address attribution

Committed after the **incomplete first run 42623887543** and before the repaired complete four-case collection. The first run produced **one fully valid original Wine case**: 8,679,052 dynamically recorded isolated Ir events, all six original states and seeded native RNG verified, with a large anonymous Valgrind function. Its **second** case failed *before collection* because the production `@njit(cache=True)` had loaded an already compiled Numba function from the prior example: the nested step dispatcher may have zero `.signatures` even though the production propagated native successfully (Numba had deserialized the complete higher-level propagator from disk). This is a scientific profiler **preflight assumption error, not any native PCC computational failure**. The incomplete raw archive is preserved [run 42623887543](https://github.com/fbreve/pypcc/actions/runs/42623887543).

## Exact repair
1. Give **each of four test cases a fresh, empty private `NUMBA_CACHE_DIR`** under its Callgrind result directory. Leave `@njit(cache=True)`, original native code, source, graph, labels and RNG unchanged. This makes each original function compile within its own interpreter before instrumentation, allowing fair JIT-native function identity discovery; the JIT warmup remains OUTSIDE Callgrind's instruction-collection window.
2. Require a real compiled `_pcc_propagate_numba_sequential` overload instead of assuming `_pcc_step_numba_sequential.signatures` is necessarily populated after a cache-loaded compiled high-level function.
3. Native Numba JIT code is often anonymously labeled **`0x....` by Callgrind** even with `NUMBA_ENABLE_PROFILING=1` and debug info. After original 2-step JIT warmup and before collection, read each Numba dispatcher compiled result's exact **LLVM registered native function entry pointer** using `overload.library.get_pointer_to_function(overload.fndesc.llvm_func_name)` and archive it. Require pointer only if the compiled overload exists; never invent a pointer or infer identity from name substring. In the independent parser, reattribute anonymous Callgrind functions ONLY IF their hexadecimal entry address is an EXACT match to one recorded native JIT pointer for that SAME ORIGINAL PROFILED PROCESS. No ranges, heuristic assignment, or address guesses. If no exact native pointer matches, verdict `PROFILE-UNRESOLVED` with raw evidence, NOT any claim that Python does more work.
4. Fix an invalid escaped hyphen in the original **report-only** Callgrind position regular expression. This had not yet executed in the partial run, and no profiler data is changed.

The **frozen original workload** remains 2 real datasets Wine/Digits ×2 labeled seeds 73013/73117, exactly original native Numba 1000 fixed iterations, same graph, same six state hashes, original RNG/stop info, same Linux CPU/Valgrind, `Ir` exclusive summation, same no-change production source guard and science-only disposition. Callgrind dynamic Ir remains an instruction metric, NOT measured elapsed CPU, energy, or cycles.

No result or threshold is relaxed, and no unverified native attribution is permitted. This fix is made before the full four-case scientific experiment and is kept in permanent evidence.
