# Frozen protocol: canonical **undirected** k-NN sparsity and particle mobility

Pre-registered **before outcomes**, based on integrated-but-unmerged draft #183 HEAD `5b2a13c59f3a7e1094957e3c1f37bf8da9dfec80`; depends transitively on draft #182, not `master`. **No production changes.** The previous directed-graph operational class-lockout cohort is *not* a canonical PCC prevalence estimate; see `experiments/GRAPH_BASELINE_CORRECTION.md` in historical archived experiments. A separate correctly canonical 50k/20-run union-10NN cohort saw zero class lockouts. This study tests one **new, controlled graph sparsity axis**, not another stopping-threshold sweep.

## Frozen design and distinct research question

- **Digits only**, standard `sklearn.datasets.load_digits`, `StandardScaler`. Build each graph independently through untouched production `pcc_graph.build_knn_graph(X, k_nn=k)`, comparing **k=3 vs k=10**. Both MUST be reciprocal union-symmetrized undirected, with no active self edges or repeated neighbor indices; record actual min/mean/max degree, connected-component count, and component sizes. Never use experimental directed `compare_dominance_stopping.prepare` or assume kNN edges only exist in one direction.
- Exactly **two labeled nodes per class**, independently selected from ground-truth Digits labels by `np.random.default_rng(seed)`, reused **identically** for k=3 and k=10 within seed. Fresh, preselected `SEEDS=(20107,20201,20309,20411)`. Same classes/vertices per seed, but different graphs yield different stochastic trajectories even with the same explicit `np.random.seed(seed)`.
- Native sequential `PCC(impl='numpy')`, `p_grd=.5`, `delta_v=.1`, `deltap=1`, `dexp=2`, **100,000 iterations with `early_stop=False`**, `es_chk=2000` unused. No native stopping, reset, force floor, reweighting, changed motion semantics or new graph option.
- Each `seed × k` has **two fresh real fits**: ordinary unobserved no-stop and a single uninterrupted no-stop fit observed at every actual iteration (including iteration zero). Total **8 exact paired comparisons / 16 actual fits**, four independent Linux Python 3.12 seed jobs; each job runs both k values. Alternate ordinary/observed order by seed and k. Require all 8 with mandatory all-cases summary; no exclusions or post-result threshold changes.

## Physical movement observation (distinguish from sampled label changes)

- Current native NumPy sequential kernel changes `part_curnode[p]` only if proposed destination has particle class tied for maximum dominance; the graph has **no self-loops**. Therefore an observed **position change between consecutive full iterations is exactly an accepted move** for that particle in these graphs. Unlike comparing 1000-step endpoints, no accepted out-and-back move is silently lost.
- A minimal **experiment-only** callback sees all 100,001 actual iterations `0…100000` (plus one final metadata notification, which must not create a duplicate physical sample). To keep memory bounded, stream particle-position deltas into per-class counters and maintain at most the previous particle position array; retain one complete low-level final snapshot. The existing experimental propagator passes `np.random.get_state()` even at every selected checkpoint; this imposes overhead and must be reported. The collector does not modify the model or draw random numbers.
- Create exactly **100 disjoint 1000-iteration windows**. Count accepted moves per class and whole-system zero-movement steps from every iteration. At each window end, record actual per-class max/min strength, number of outgoing neighbor entries whose current dominance favors the class, and class dominance mass over initially unlabeled nodes. Because each particle begins at its own labeled home and each active vertex has nonzero degree, every particle makes one valid destination visit per iteration; assert all k graphs have no isolated vertices. Do not infer rejected attempts from isolated component rules without inspecting destinations.
- An **operational class lockout** is fixed in advance: **five consecutive 1000-step windows with zero accepted moves for every particle of the class, max strength <= 0.01, and no currently winning outgoing neighbor entry**. This is not proof of irreversible trapping; report first event, recoveries if any, longest zero-acceptance window streak per class, numbers of affected classes and fraction of attempts accepted per class. A single stationary particle or short streak is **not** class lockout. Calculate longest individual stationary streak and never-moved particle count as separate measurements.
- Same seed and label mask across k, but never assume same RNG trajectory across different topologies. Report held-out accuracy on exactly the same initially unlabeled nodes for k=3 and k=10, with a paired descriptive signed accuracy difference; this is not evidence that class lockout causes any accuracy difference.

## Integrity gates and artifacts

1. **Every seed×k ordinary/observed pair must match bitwise** on six full final state arrays (predictions, positions, strengths, distances, dominance, normalized ownership), entire native stop metadata, *all five* global MT19937 state fields and next 16 random draws. Final physical snapshot must reproduce native model state **before ownership normalization**, complete RNG and iteration 100000.
2. Enforce exactly **100001 unique physical calls**, 100 windows × all ten classes, class movement counts, valid labeled-state preservation, finite/simplex dominance and finite particle strengths at final. Retained metrics O(100 × 10 + particles + nodes × classes). Explicitly record graph connectivity and actual degree, not just the requested k.
3. Require **all four distinct seed JSONs and eight condition records**; reject missing, duplicate, corrupt, or unexpected metadata. Archive actual per-window class metrics, final full-run parity flags, accuracy and descriptive wall times plus per-run dependency inventories.
4. Tests of counter semantics must cover an accepted **out-and-back** across a 1000-step endpoint, distinguish per-particle stationary interval from whole-class lockout, verify no duplicate final physical row and reject skipped iterations. Do not infer a baseline speedup from host timings.
5. No gate on finding lockout: both zero and positive events are valid scientific outcomes. The **only hard gates are integrity and complete cohort**. Interpretation remains exploratory with four new seeds; no reset/force-minimum movement, stopping-policy, label-distribution, or production-graph change is authorized even if k3 generates a lockout.
