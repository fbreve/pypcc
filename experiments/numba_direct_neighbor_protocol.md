## Distinct candidate vs historic already explored paths
Previously rejected CPU work includes greedy fused loops [#107](https://github.com/fbreve/pypcc/pull/107), bounds-check sharing [#114](https://github.com/fbreve/pypcc/pull/114), probability scratch writes [#115–#116](https://github.com/fbreve/pypcc/pull/115), on-demand prefix [#71](https://github.com/fbreve/pypcc/pull/71), and fused dominance maximum [#65/#82](https://github.com/fbreve/pypcc/pull/82). Previous new Numba global-potential cache [#213](https://github.com/fbreve/pypcc/pull/213) was NO-GO with exact state parity and <8% Digits/<5% Breast Cancer observed improvements. **Do NOT repeat those changes.**

The exact original `_pcc_step_numba_sequential` assigns `neighbors = neib_list[curnode, :k]` **inside the hot per-particle loop**, then reads `neighbors[i]` in greedy scan and `neighbors[choice]`, `neighbors[idx]` for greedy and fallback/random choice. Hypothesis: Numba materializes slice-view metadata per particle; using direct `neib_list[curnode, column]` may reduce CPU without changing memory representation, RNG or floating math. This is NOT established: LLVM may optimize away the view already.

**Exact candidate in a separate independently compiled copy of true original Git `pcc_numba.py`:** remove exactly `neighbors = neib_list[curnode, :k]` line; replace in **one frozen `_pcc_step_numba_sequential` function** the single `next_node = neighbors[i]` with `next_node = neib_list[curnode, i]`, the single `next_node = neighbors[choice]` with `next_node = neib_list[curnode, choice]` and the two `next_node = neighbors[idx]` with `next_node = neib_list[curnode, idx]`. All other original source byte-identical, including active-k guard, negative/out-of-range checks, probability, distance/strength, NaN/overflow branches, `np.random` draw order, weighted selection, movement, early stop, max calculation. No `@njit` signature, dtype/layout, public parameters, seed or validation changes. Original Numba is loaded and JIT compiled separately from the real frozen Git blob; candidate generated by strictly counted unique text anchors and JIT compiled independently, **never monkeypatch global imports**. High-level `PCC(impl='numba')` is run with per-instance backend selection retaining the native `pcc_propagate_numba` name and Numba C-order dominance for >=8-class Digits.
