# Precommitted observation: current-master graph stages and installation

**Independent SCIENTIFIC DRAFT, no production patch.** Frozen on exact production `master` `c1073ae53ea785031de9e474b678e94f44a2124d`, after merges #192/#195/#198/#201/#203/#205/#207. Commit this protocol before instrumentation or trials. Goal: identify which current-stage operations actually consume CPU when constructing a fresh undirected kNN graph and when installing that graph using `set_graph`, without sacrificing the **intentional dense padded int64 neighbor matrix** and its propagation CPU advantage.

## Why an additional observation is warranted (not redoing rejected work)
Earlier [#191](https://github.com/fbreve/pypcc/pull/191) attributed old graph-build time to (fit+query), CSR, dense scatter and led to already merged #192/#198; its timings precede these changes. [#193](https://github.com/fbreve/pypcc/pull/193) examined alternative sklearn engines; **do not resurrect brute/KD/Ball heuristics** or change tie semantics. [#200/#201](https://github.com/fbreve/pypcc/pull/201) already optimized `set_graph` active-neighbor validation; current time needs measurement, not another guess. [#208](https://github.com/fbreve/pypcc/pull/208) observed a full graph-build bottleneck when rebuilding (especially Breast Cancer), while clarifying that `set_graph` is timed OUTSIDE `fit_predict`. **`PCC.build_graph(data)` and `PCC.set_graph(neib_list,neib_qt)` are two different public paths**: the former calls build_knn_graph and directly installs its arrays; the latter validates/converts/copies already-prepared arrays. Do not blindly add set_graph to the build_graph path as if both were always executed.

- Pin both `pcc_graph.py` **Git blob source** and repository production source diff against exact master; verify zero changes in `pcc.py`, `pcc_graph.py`, `pcc_numpy.py`, `pcc_numba.py`, `pcc_step.pyx`, `pcc_validation.py`, `setup.py` and `benchmarks/`.
- Read the actual frozen original `pcc_graph.py` via `git show`, compile that verbatim into an isolated module as **unobserved reference**. Generate an instrumented cloned module by inserting ONLY `time.perf_counter_ns()` stamps into the exact function body at six original source boundaries. Guard each insertion marker has exactly one match. Never alter a graph expression, call argument, neighbor search engine, dtype, CSR cleanup, padding or edge order; no monkeypatched NumPy, SciPy, sklearn or PCC backends.
- Separate clock intervals: (1) validation/preparation before sklearn; (2) `NearestNeighbors(...).fit(data)`, including its original constructor; (3) `kneighbors(data)`; (4) directed input rows + CSR allocation; (5) symmetrization/diagonal cleanup/binarization; (6) `np.diff` degrees + **current vectorized** padded dense matrix fill. Measured internal intervals sum to instrumented internal elapsed time (clock overhead itself included, not a zero-overhead hardware profile). Separately measure matched **whole source-original vs timestamp-observed graph build** to characterize probe observer overhead: don't claim stage timing equals an unmodified build without caveat.
- On both GitHub Actions Ubuntu/Windows native Python 3.12, fixed `OPENBLAS_NUM_THREADS=OMP_NUM_THREADS=MKL_NUM_THREADS=NUMBA_NUM_THREADS=1`, use original sklearn `algorithm=auto`, Euclidean Minkowski p=2, n_jobs=1, undirected union graph, no new graph semantics.
