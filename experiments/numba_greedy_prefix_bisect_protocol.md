**New, narrow hypothesis:** the current actual **Numba** sequential greedy source already computes `slices[i] = cumulative_probability` with the exact original floating-point sum order. Its subsequent first-index search `rand_val < slices[i]` is O(k), where k is ACTUAL undirected reciprocal/symmetric graph node degree. For actual k >=8 on nondecreasing prefixes only, replace the final scan by first-index `bisect_right(slices,rand_val)`, implemented inline using `lo,hi` integers and the SAME strict `rand_val < slices[mid]` test. If no such prefix is found (edge rounding), retain original `choice=0`. Preserve all original weight/probability/slice accumulation loops, inf normalization, native `np.random.uniform(0.0,total)`, fallback `np.random.randint(k)`, direct-random branch, original dominant-node arithmetic, current #228 native full-row argmax, stopping and arrays. For degree <8 or any observed **nonmonotonic prefix**, use the unchanged original linear selection, including same strict comparison and default choice. Monotonicity is tracked during existing original prefix accumulation AND inf-rescale accumulation without reordering any sums; no additional allocation. Do not try Cython or change dense padded int64 neighbor storage.
