# Frozen Numba exact row-max checkpoint cache: CPU-for-memory prospective scientific trial

**Experimental only, DRAFT unmerged; PR target production `master` commit `d25d5446b7fa51cc0264a496b7eea87dbb11f1fc`.** Commit this protocol before any candidate implementation, timing or CI. The goal is **CPU savings** in Numba with original `early_stop=True`; extra `n_nodes × float64` temporary memory may be desirable, but memory savings alone do not justify any change. Intentionally preserve original padded, ordered, C-contiguous int64 `neib_list`, all other native backends and `fit_predict` logic.

## Exact problem and prior work
[PR #212](https://github.com/fbreve/pypcc/pull/212) measured actual full `fit_predict` current-master CPU. On Breast Cancer and Digits at 30k, Numba early-stop monitoring incurred roughly 12–15% extra whole-fit CPU with **no stop**; Wine stopped early with large real savings. Numba `_pcc_step_numba_sequential` already determines the final per-destination `max_dom` for the existing movement decision, and `_pcc_calc_mmpot_sequential` presently rescans every node×class every 10 iterations. Cython [#177–#179](https://github.com/fbreve/pypcc/pull/178) already evaluated and merged an exact *per-node rowmax* cache (and discovered that a per-particle runtime flag regressed default OFF). This experiment is a **new Numba-specific implementation and independently preregistered test**, not an alternate stopping criterion, changing `es_chk`, revisiting Cython, or a graph/RAM compression effort. Existing Numba scalar potential monitor must remain a callable reference.

## Candidate constrained to only the Numba native propagation
- Scientific code uses the **exact original Git blob** `pcc_numba.py` at frozen base, loaded in a distinct Python module, compiled with real `@njit`. Another clone of this same original Git blob is transformed via guarded, unique source anchors to create a scientific candidate, and compiled separately. Both are paired on the **same OS and same invocation**, with real Numba JIT precompiled before timings. The source transformation must leave the original, the high-level model, RNG, public graph, native NumPy and Cython, any installed package source and regression suite untouched. Runtime source guard demands zero diff in `pcc*.py`, `pcc_step.pyx`, `setup.py` and `benchmarks/` between current experimental branch and production base.
- Candidate contains a distinct specialized `_pcc_step_numba_sequential_cached` compiled hot loop **identical** to baseline step except for an additional `row_max_cache` parameter and **one write of computed max_dom** for visited unlabeled nodes; no per-particle runtime cache switch in the baseline/default-off step. Preserve original greedy/random choices, original NumPy RNG draws, complete dominance/strength/distance/ownership and particle movement semantics. Preserve original `_pcc_step_numba_sequential` as a separate untouched specialization for `early_stop=False`.
- When `early_stop=True`, allocate `row_max_cache=np.empty(n_nodes,dtype=np.float64)` **once per propagation call**, initialize by scanning the original `dominance` rows in exact original class order **before any particle update**. On a destination update, assign the row's already computed final `max_dom` only if that row is unlabeled, since labeled dominance is unchanged. At the original `it%10==0` checks, sum all cache entries in **original node index order** and divide by n_nodes; NEVER maintain an incremental rolling global float sum, change comparison `>` versus `>=`, threshold, check cadence, or break condition. When `early_stop=False`, call completely unchanged original compiled step/propagation path, with **no cache allocation**.
- The scientific candidate may expose explicit *experiment-only* metric-verification specialization to recompute and compare every checkpoint on selected 2001-step tests; it must not enter measured production-like cached path. Reject any metric difference at a checkpoint **bit-for-bit**.
- Full current original wrapper input validation, seed normalization and propagation_info return must be preserved; run original model `PCC(impl="numba")` with per-model backend substitution only, retaining `__name__="pcc_propagate_numba"` for Numba >=8-class **C-order** dominance. No changing global import assignment, production files or kwargs. Confirm backend source compiled from actual original Git blob; return_info=True only in observational audit, exactly as existing benchmark instrumentation.

## Frozen CPU, parity, memory and graph workload
- GitHub Actions Linux/Windows Python 3.12 (independent hosted CPUs) and thread settings `OPENBLAS_NUM_THREADS=OMP_NUM_THREADS=MKL_NUM_THREADS=NUMBA_NUM_THREADS=1`. Real 4 offline original standardized sklearn datasets **Iris/Wine/Breast Cancer/Digits**, default undirected **union kNN=10** with **3 original class-balanced labeled homes per class**, label seeds **62011/62137**, original seed `0`, `p_grd=.5,delta_v=.1,deltap=1,dexp=2,es_chk=2000`. Two original modes: monitored `early_stop=True` and fixed `early_stop=False`. Cap **30k steps** with 6 alternating original-vs-candidate complete `fit_predict` CPU timing pairs per dataset/seed/mode/OS. Total: 4 datasets × 2 masks × 2 modes × 6 pairs × 2 OS = **192 paired whole-fit CPU observations / 384 native fits**, excluding one independently warmed original and candidate (32 warmups across OS) and source compilation. All paired timing samples are retained without outlier trimming. Preserve repeated same-source native outcome and actual original stop iterations, verify whole predictions, dominance, particle positions/strengths, distance tables, normalized `owndeg` **six exact array SHA256 hashes** and next Numba RNG draws after fixed seed for each pair/mode; Numba RNG introspection via a separate `@njit` draw after fit must be run **after** timing and must not perturb within-fit states. Backend identity / class memory layout and graph fingerprints exact; never assert Cython/NumPy share Numba RNG.
- For early-stop pairs, use real stopping criterion unchanged: `stop_reason`, `effective_iterations`, `stalled_checks`, `stop_max` and complete `checks` identical; the non-stopped cases (censored at 30k) still require exact equality. Candidate fixed path should call true untouched compiled step without any cache. For each dataset×seed×OS run **two short 2001-step opt-in instrumented candidate checks**, re-evaluating potential at **all 201 original 10-step checkpoints** against actual original calculation, no missing points (16 verification fits total across OS). Recomputed potential uses no RNG.
- Separate `tracemalloc` peak measurements (three original/candidate **full-fit pairs** per dataset×seed×mode×OS, **96 tracked pairs**) measure Python-visible allocation including the cache and audit overhead but are NEVER used as the timed CPU result. Extra temporary memory is permitted to save CPU; gate allows candidate median tracked peak ≤ original + `8*n_nodes + 2 MiB` (tracemalloc != native process RSS).
