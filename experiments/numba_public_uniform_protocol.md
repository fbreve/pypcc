## Distinct hypothesis
Research #219 actually attributed native RNG/TLS instructions; #220 experimentally reused the private Numba random state pointer, yielding Linux CPU 6–11% but Windows/Digits 2.4–3%, a preregistered **NO-GO** with compatibility concerns. No changes to private `randomimpl` are acceptable. Here make ONLY ONE exact source change to the *public* native Numba greedy branch: `rand_val = np.random.uniform(0.0, total)` → `rand_val = np.random.random() * total`. The former is implemented using a uniform `0.0 + (total - 0.0) * np.random.random()` in existing Numba/LLVM, so mathematically this might be bitwise equivalent and marginally cheaper but may be optimized identically already; DO NOT assume correctness or speedup. No other changes to greedy policy, prefix sums, max overflow rescaling, random-only path, random integer sampling, class dominance, distance updates, strength, graph, or stop checks. Neither original nor candidate uses internal Numba C/LLVM APIs. Both remain `@njit(cache=True)` from current master, each independently JIT compiled from a physical source file.
