# Frozen observational audit: repeated PCC fits on one installed graph

**Scientific-only draft, never a production merge.** Pin original production source at commit `b4c100bd22eeff1979a1a581bc73682b8c3705b8`. Commit this protocol BEFORE creating any auditor or taking CPU samples. No production source, graph, backend, RNG, public API, stopping or padded dense `int64 neib_list` changes. This study is orthogonal to #221 and #222: #222 measures one class-discovery hunk, while this measures the *current original* repeated-fit initialization/allocation phases and structural reuse safety.

## Scientific question
With ONE original graph installed ONCE using `set_graph` and ONE original PCC model, how much CPU/wall is attributable to preparing labels, initializing particles and their `uint8` distance table, initializing nodes/dominances/own-degree, creating propagation scratch arrays, actual native propagation, and postprocessing when `fit_predict` is called repeatedly with alternating labeled masks? Can any costly structure safely be reused across fits given the original rollback and previous-state reference semantics? This is attribution, NOT a performance GO experiment. Do not claim a speedup or merge from this profile.

## Frozen workloads
- Actual sklearn standardized Wine, Breast Cancer, Digits, **undirected ordered production union kNN10**; synthetic symmetric two-neighbor ring graphs of **30,000 or 100,000 nodes** and **2, 10 or 50 classes**. Ring graphs are controlled initialization stress tests, NOT substitutes for the three real datasets.
- Two independent balanced 3-labeled-nodes-per-class masks, with deterministic seeds **82013 and 82117**. Ring ground-truth classes repeat round-robin; each mask selected independently and alternated. Native explicit propagation seed **29** on each fit. Original `p_grd=.5, delta_v=.1, deltap=1, dexp=2, es_chk=2000`.
- NumPy, Numba and compiled Cython backends with original native identity checks. Stop disabled for **0 and 5 iterations** on real and ring cases. Also original 500-iteration fixed run **only on real datasets and compiled Numba/Cython**. No mode or dataset omitted posthoc.
- For each OS×case×backend×iteration cohort, **4 counterbalanced pairs** of control and instrumented batches, each of **8 consecutive complete fits on the SAME single model and original once-installed graph**, alternating the same two label masks. The two arms have independent PCC instances but share identical immutable input graph values. The first batch follows original/traced order and next reverses. No graph rebuilding or reinstallation between fits; Numba warmed separately and JIT excluded from CPU measurements.
- Every 8-fit batch gets original `process_time_ns()` and `perf_counter_ns()` around the ENTIRE batch; Windows process time quantization is reported, not silently replaced. Hashing and all state/RNG checks occur OUTSIDE each timed batch. Instrumented class only wraps private Python method boundaries and original native backend entry/exit using `functools.wraps`; the actual backend object, original C/F dominance decision, and original code remain unchanged. Report probe overhead by comparing original uninstrumented versus traced batches on same OS, not by assuming wrapped calls have zero cost.
- Timing attribution for traced arm: full fit, total `__genParticles` (includes distance-table fill), total `__genNodes`, entire `__labelPropagation` and its true native-propagation portion. The residual includes validation, class mapping, scratch setup and final postprocessing and MUST NOT be mislabeled as individual stages. No attempt to infer CPU by subtracting wall time phases; per-phase probes are **wall-only**, paired full-batch CPU/wall are the primary measurements.
- Require exact six final model arrays (prediction, dominance, positions, strengths, distances, owndeg), ordered graph, labels, C/F dominance layout, and next true NumPy/Numba RNG sample where applicable for EVERY matched original/traced fit. Verify old fitted arrays remain unchanged and have independent identities after a subsequent successful fit; verify invalid-seed/shape fails without changing the existing model state. Record relative allocation sizes of `dist_table`, `dominance`, `owndeg` and scratch arrays and distinguish these logical `nbytes` from RSS or peak memory.
