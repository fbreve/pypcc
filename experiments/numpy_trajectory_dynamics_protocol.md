# Frozen scientific pilot: native NumPy PCC trajectory dynamics and stopping

**This protocol is frozen before experimental data are computed.** Independent scientific branch `experiment/numpy-trajectory-dynamics-v1` is based on the completed but **unmerged** NumPy observer draft PR #182, Git SHA `bd3ab77d98b4ac50990e7bafcaf398cf5a29b8f9`. It is intentionally a *separate dependent PR*, not a modification to the validated #182 branch. No model mathematics, graph construction, random sampling, high-level model API, stopping rule, Cython/Numba, or installed package is changed.

## Purpose and limitations

Scientific questions: (1) Can classifications that match at consecutive *100-iteration window endpoints* nonetheless flip and revert inside the window? (2) How often do particles stay on the same node for many steps, **without claiming this proves they are trapped**? (3) When the existing potential-based early-stop rule stops, does a **separately seeded, uninterrupted no-stop trajectory** match its exact native particle state/RNG at that time, and how different are its predictions after continuation? This is a descriptive pilot, **not** a new stopping criterion or a claim that any patience setting is safe.

Use **original undirected reciprocal union-10NN** graphs built by current production PyPCC from standardized Iris/Wine/Breast Cancer/Digits; exactly two labeled vertices/class with independent `default_rng` for label selection. Native `impl="numpy"`, sequential, `p_grd=.5`, `delta_v=.1`, `deltap=1`, `dexp=2`, `max_iter=6001`; fresh deterministic seeds **18013, 18109**; Python 3.12 on Linux first. Require a complete **4 datasets × 2 seeds = 8 triples / 24 real fits** and a mandatory strict summary. Never omit nonstopping cases. CI matrix runs one dataset/job. Windows replication is a later preregistered study, not silently implied.

## Each triple

1. **Normal unobserved no-stop fit** (`early_stop=False`): save six complete final arrays (predictions, particle positions, strengths, distances, dominance, normalized ownership), entire global NumPy MT19937 state, next 16 random draws and native stop info.
2. **Actual normal potential-stop fit** (`early_stop=True, es_chk=10`): use a tiny final-only private observer that copies five raw native buffers, derived assignments and full MT19937 state only when receiving the real final callback. Save actual early-stop iteration, native reason, and finished classification and accuracy. This uses the **existing** code's stop policy; `es_chk=10` is *aggressive and experimental*, not the default or a recommendation.
3. **Full 6001-step uninterrupted no-stop fit** with a **nonmutating per-iteration streaming observer**, using `wants(k)=True` for every actual iteration `k=0,…,6001`. **No full-array archive at each iteration**: retain only O(nodes × classes + particles) current references copied as small previous-state/window baselines, 100-step aggregates, and exactly one full raw state+RNG checkpoint at the stop fit's actual ending iteration. Require every iteration 0 through 6001 once and the genuine final notification. For this fit, require **bitwise equality** of the same six final arrays, native stop info, full MT19937 state, and next 16 draws versus fit #1, without tolerance.
4. At the actual stop iteration, require **exact raw-state and complete RNG equality** between the stopping fit's final callback and the corresponding in-run no-stop callback (six low-level derived/native arrays). Shadow-evaluate the **exact preexisting potential-stop comparisons at iteration 1, 11, 21, ...** from the uninterrupted trace, with original `stop_max`, and assert the *first* computed trigger matches actual native ending iteration when early stop occurs. If it doesn't stop by 6001, assert no trigger.
5. **Window metrics:** fixed, disjoint windows `[0,100], [100,200], …, [5900,6000]`, each with 100 transitions. A window is endpoint-stable if **all** predicted node labels at start and end are equal; within-window transient reversal requires at least one node to differ from the starting assignment at an *intermediate* iteration and to return by the end. Record counts of endpoint-stable windows containing a reversible excursion and reverted nodes, and total individual per-step label flips. All classification metrics keep originally labeled nodes fixed. Note that aggregate node counts across windows are *not unique nodes over the entire run*. The remaining `6000→6001` transition is still included in per-step counters but is excluded from full windows.
6. **Motion metrics:** at every iteration, compare native particle positions to the previous iteration, count changed-position events, zero-motion iterations, per-particle longest stationary streak, never-moved particles, and how many particles end with stationary streak ≥100. **Unchanged position is not proof a movement was attempted or rejected**: isolated vertices, random choices and rejected moves are not distinguishable from this observer alone. Do not conflate motion statistics with label-stability.
7. **Outcome difference:** for early-stopping cases, compare stopped predictions at the true stop against the 6001-step no-stop final predictions, count unlabeled-node disagreements and report unlabeled accuracy on held-out true dataset labels at both endpoints. For nonstopping cases, report 0 disagreement only if final exact parity passes. Do **not** claim statistical superiority from eight exploratory pairs.

## Mandatory integrity and reporting

- Require genuine 6002 unique per-iteration streaming callbacks, not independent prefix replays; final callback merely confirms the last state and never appends a duplicate step.
- Require complete 8/8 JSON results and strict per-triple parity/instrumentation/potential checks; archive per-seed detailed 60-window counts + per-particle streak summaries and environment inventories, without selectively dropping inconvenient results.
- Running the full scanner may impose **high opt-in overhead** (unlike sparse #182 checkpointing); record wall time only descriptively. Do not compare these numbers to previously frozen sparse-snapshot overhead gates or change speed targets based on outcomes.
- If tests fail, investigate and report rather than adjust analysis definitions after seeing results.
- **No master merge** and no algorithmic reset/force-minimum movement modifications from this pilot. The dependent PR remains draft until results are reviewed.
