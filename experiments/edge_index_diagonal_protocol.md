# Precommitted protocol: avoid redundant diagonal cleanup for loop-free edge-index graphs

**Frozen before candidate source change and before CI outcomes.** The exact original production comparison is current `master` commit `35dc81caf0388be8ea1729837ea6d54358b53964`, which already contains the independently merged #192 exact ordered CSR offset optimization. Do not stack on drafts #182–#191/#193. This experiment modifies **only `pcc_graph.build_graph_from_edge_index`**; original `build_knn_graph`, all NumPy/Numba/Cython kernels, graph topology, ordering, RNG, prediction and stopping behavior are not authorized to change.

## Preregistered optimization and its premise

Original `build_graph_from_edge_index` first creates an **undirected boolean** CSR from concatenated source/destination edges, then unconditionally calls `adj.setdiag(0)` and `adj.eliminate_zeros()` even for input edge lists with **no self-loops**. The CSR constructor stores only nonzero boolean `True` data and coalesces duplicate Boolean entries by OR, so when no input `src == dst` exists there cannot be stored diagonal edges or zeros from this construction. A local exploratory pilot with current container SciPy/NumPy suggested this cleanup can consume substantial overhead for *sparse* edge-index graphs with many vertices/isolates, yet a no-loop scan can mildly penalize denser graphs. These local findings motivated this *prospective* independent CI experiment; they are not CI-confirmed or general performance claims.

**One frozen source candidate:** keep every other statement, but perform the old `adj.setdiag(0); adj.eliminate_zeros()` exactly as before **only if `np.any(src == dst)`**. For self-loop input the original path is unchanged. Do **not** pre-filter endpoints, change invalid index validation, change `num_nodes == 0` shortcut, alter dtype, sort neighbor indices, drop reciprocal or duplicated edges, optimize the kNN builder or introduce a size-dependent heuristic. Boolean duplicate coalescing and `adj.data[:] = 1` remain exactly as in the original.
