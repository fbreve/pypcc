## Novel hypothesis and exact source
The current `pcc_numba.py` uses `@njit` **without disk cache** at its four decorators. Repeatedly starting a new Python interpreter therefore typically recompiles the same native machine code. Candidate only changes **all four** original `@njit` decorators (seed helper, step, potential, propagation) to `@njit(cache=True)`, with **zero changes to any function body, parameters, call sites, floating math, NumPy native RNG, stopping, public API, graph or memory layout**. Dynamically prepare two real *filesystem-backed* Python module copies from the **same pinned canonical original Git blob**: source-original plain decorators and source-candidate cache decorators. Never monkeypatch installed production modules, never modify source files in Git other than experiment scripts/docs/workflow. Verify exactly 4 decorator replacements; compare entire canonical source with only that difference, and guard all pcc*.py, setup.py and benchmarks/ against source changes.
