## New question, distinct from previous experiments

The Cython default-on per-node early-stop potential cache (merged #178/#179) currently allocates one `float64[n_nodes]` buffer, then calls `_pcc_initialize_rowmax_cache(dominance,n_nodes,c,row_max_cache)`, which scans the *entire* initial `dominance` matrix O(n_nodes*c) **once per fit**, even when the high-level `ParticleCompetitionAndCooperation.fit_predict` has just initialized every row deterministically: for known labeled nodes exactly one column is 1 and others 0; for every unknown node every class is exactly the Python `1.0 / c` value. The exact original initial row maximum therefore is 1.0 if `mapped_labels[i] != -1`, else precisely the original initial uniform value, regardless of whether C/F layout.

Test replacing this **specific redundant initial scan** with an O(n_nodes) fill from the already existing `labels` vector **ONLY when the actual normal high-level original PCC class has just constructed that canonical dominance state**. This is NOT prior #177/#178 (incremental potential maintenance once fits are running), #202 (node matrix construction), #199 (normalization), #226/#228 (post-propagation argmax), #74 (Cython roulette), or #221/#234 (Numba greedy/RNG). Keep every original particle update, per-node cache update, global sum accumulation order, checkpoint schedule, dynamics and RNG unchanged.
