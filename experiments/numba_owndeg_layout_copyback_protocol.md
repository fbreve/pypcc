## Hypothesis and source scope

Production `__genNodes` allocates `owndeg` as Fortran-order float64 for all native backends, while actual Numba many-class `dominance` is already C-order. The native kernel updates `owndeg[next_node, particle_label]`; C-order `owndeg` could improve local writes on many-class graphs, but C layout changes NumPy row-sum floating reduction order and is an externally visible output property. Evaluate a deliberately conservative variant:

1. In unchanged actual `__genNodes`, allocate ONLY the actual Numba `c >= 8` `owndeg` as C-order, using the existing `use_c_order` decision; all other backends/cases remain F-order. Do not change original padded dense int64 graph, numerical type, dominance layout, class mapping, native backend code or random draws.
2. Immediately AFTER the unchanged true native `propagate_fn(...)` and exact post-propagation label assignment, and BEFORE the original `np.sum(self.owndeg, axis=1, keepdims=True)`, copy this **temporary C** `owndeg` to a new Fortran-order array only when it was created in C layout. The original full rowwise sum, zero-row guard and division execute on F-order just as in master. Final `self.owndeg` is F-order; its exact numeric bit pattern and other final states must be identical to master.
3. No production source files may change in the science branch. Build one complete PCC candidate dynamically from the exact original `git show <sha>:pcc.py`, with only the two guarded source replacements. Original complete-source `PCC` is the untouched control; original actual Numba/Cython/NumPy dispatchers remain unchanged. For nonexistent optional Numba and for Cython/NumPy, candidate must use ORIGINAL F allocation and must not copy-back.

This adds a deliberate native-to-F copy, so **memory traffic may worsen**, especially on short/zero-iteration fits. Exact layout and state parity are hard gates; even if native propagation accelerates, full-fit process CPU after the copy is decisive. Rejected #199 must not be reopened by post-hoc criterion changes. If C layout fails semantic or performance gates, record NO-GO and close without merge.
