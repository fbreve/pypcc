## JOSS's current pre-review gates and risks

The official [pre-review criteria](https://joss.readthedocs.io/en/latest/submitting.html) are stricter than simply having a GitHub repository with a license. Required gates include public iterative development for more than six months, **documented actual research use**, open-source practices for contributors, a complete functional install/testable package and a scholarly role extending beyond a one-off utility. A solo-maintained package can qualify, but public history, releases, tests, contribution policies and examples should be discoverable. It is not enough to intend future use, and a published paper about the **2012 mathematical method** is not automatically a publication using this **2026 software implementation**.

The latest [paper format](https://joss.readthedocs.io/en/latest/paper.html) calls for a high-level summary plus sections named **Statement of need**, **State of the field**, **Software design**, **Research impact statement**, and **AI usage disclosure**, together with authors, affiliations, references and acknowledgements where appropriate. The paper should be **750–1,750 words**, not API documentation; API details belong in the repository docs. Human author(s) need to verify every claim, choose the author list, and disclose actual AI use consistent with the latest [policy](https://joss.readthedocs.io/en/latest/submitting.html).
