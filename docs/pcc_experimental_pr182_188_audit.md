## 2. What the experiments support — and what they do not

- **The old severe trapped-particle examples came from directed outgoing-kNN graphs**, not the same undirected graph construction used by canonical PCC. The corrected union-symmetrized graph studies #184–#188, including deliberately disconnected/bridged artificial topology and original connected graphs, did not observe **whole-class operational lockout**, and did not observe a complete 1,000-iteration **class zero-accepted-movement** window in their full per-step cohorts. This does **not** prove immobility is impossible on every dataset, edge configuration, label mask or longer horizon. An individual rejected move, an isolated node, an unreachable component/class and a whole-class lockout are different concepts.
- **A class-lockout absence does not imply prediction quality is high.** The bridge studies found some large accuracy shifts despite movements continuing throughout. Increasing cross-cut transitions boosted physical traffic but yielded mixed and dataset-dependent accuracy changes, without evidence that traffic *caused* those changes.
- **Labeled-home selection matters, but no default is identified.** High-degree selected homes helped Digits on average but underperformed the random strategy on Breast Cancer. Degree also correlates with a retrospective true-class neighbor-agreement diagnostic, so one cannot ascribe all outcome changes to degree alone. The low/high candidate pools used **ground-truth class membership before labeling** to ensure identical class budgets: this is an **oracle** sensitivity analysis and cannot be deployed as a genuine unlabeled-node selection scheme.
- **Stopping remains a separate question.** The small #183 pilot deliberately used unusually aggressive `es_chk=10`, not production `es_chk=2000`. The earlier independent [48-condition canonical undirected held-out P10 vs original potential pilot (#174)](https://github.com/fbreve/pypcc/pull/174) already studied stopping and did **not** justify changing the default. Do not take short-run aggressive-stop reversals as evidence that production stopping is broken, nor infer that longer fixed iterations always improve accuracy.
- **No new algorithm is validated:** the NumPy observer has been proved to preserve *tested* trajectories when instrumented, but a read-only collector is not itself a classification improvement. No evidence supports moving particles by force, resetting strengths, creating teleports, changing default k, enforcing degree-based initial supervision or altering production stopping.

### Important #182 interface/safety caveat

Reviewing the actual `pcc_numpy.py` patch reveals that the *callback is provided references to the native, live NumPy arrays* (`dominance`, particle positions/strengths, distance table, raw ownership). The provided `ContinuousNumpyObserver` copies data and respects its own bounded-retention budget, and the opt-in study verifies precise state/RNG parity **for tested observers**, including an installed-wheel contract and default-off master comparisons. **However, arbitrary third-party callbacks can mutate the writable live views**; the argument is *not enforced read-only*. A callback can also raise after partial propagation, leaving RNG side effects (the normal high-level fit has documented nontransactional RNG behavior on failure). Passing a fixed bound for retained snapshot bytes does **not** impose a bound on an arbitrary callback's transient allocations, CPU usage or side effects.

Therefore **do not advertise the callback interface as a public, safe or universally non-interfering observer**. Before considering #182 for production, require an explicit decision about whether to expose any observer at all; if needed, isolate it in an internal-only diagnostic build or design explicit snapshots/immutable data at an acceptable measured cost. Add malicious/mutating callback tests, in-progress callback failure semantics and a fresh unchanged-master-vs-candidate performance check before merge. Do **not** cherry-pick the full 27-file PR merely to preserve its scientific reports.

## 3. Recommended disposition and branch hygiene

1. **Keep #182–#188 open, draft and unmerged** at present. Archive them as a coherent research lineage rather than merging seven stacked scientific workflows into `master`. Do not close or delete branches without separate user approval; all findings and machine-readable artifacts currently remain discoverable.
2. **Decouple preservation from adoption.** This independent master-based documentation PR is the compact index and decision record, with links to each precise frozen artifact. It can be reviewed/merged on its own without silently adding any experimental executable code.
3. **Only if production diagnostics are explicitly needed later**, extract a separate minimal audited tracer to a new, single-purpose PR directly against contemporary master. Include only that required, well-defined feature and carefully scoped tests; do not merge the entire seven-PR dependency chain.
4. The next task is **performance triage of existing production backends** against the already archived fixed-iteration and stopping campaigns, *not another graph/lockout pilot*. The accompanying [performance re-entry plan](performance_reentry_after_particle_audit.md) specifies short, prospective and appropriately scoped measurements before code changes.

## 4. Evidence hierarchy, freezing and scope

The full scientific CI pairs compare **same graph / same initial labels / same backend** observed-versus-ordinary trajectory, including six final arrays, native stop metadata and NumPy MT19937 state + next draws. This is compelling reproducibility evidence **within a tested configuration**, not equivalence across NumPy/Numba/Cython (which have different RNGs), different graph-dose arms or hardware. A horizon of 100,000 iterations is a **fixed observation cap**, not convergence. Four seeds within the same dataset do not represent four independent datasets or establish general population prevalence. Hosted CI timing is not an uncontended native hardware performance benchmark.

This central record intentionally preserves both null results and undesirable accuracy observations; it does **not** retroactively redefine the experiments or claim a scientific improvement. Future changes to production require a separate explicit diff, fresh regression, equivalence analysis and independently predeclared performance gates.
